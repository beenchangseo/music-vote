# 실시간 반영은 내용 없는 broadcast 알림으로 한다

같은 합주방을 열어 둔 화면들은 Supabase Realtime broadcast 채널 `playlist:{shareCode}`로 "바뀌었다"는 신호만 주고받는다. 신호에는 무엇이 어떻게 바뀌었는지 싣지 않고, 받은 화면이 서버에서 값을 다시 받아간다.

`postgres_changes`로 `votes` 테이블 변경을 구독하면 변경된 행이 그대로 클라이언트에 도착한다. 익명 모드에서 투표자를 가리는 [ADR 0011](./0011-anonymous-mode-hides-voters-in-payload.md)의 결정이 실시간 경로에서 다시 뚫리므로 쓰지 않는다.

신호는 1초 간격으로 묶어 처리하고, 보이지 않는 탭은 갱신을 미뤘다가 돌아올 때 한 번만 받아온다.

## Consequences

- 서버 렌더 값은 `router.refresh()`로, 셋리스트와 댓글처럼 클라이언트가 따로 받아둔 목록은 이미 열어본 것만 다시 받아온다.
- 알림은 변경을 만든 화면이 보낸다. 그 화면이 알림을 보내지 못하면 다른 화면은 다음 신호나 재방문까지 예전 값을 본다. Vercel Cron의 자동 확정처럼 서버가 혼자 만든 변경도 즉시 전달되지 않는다.
- 채널은 공개 채널이라 공유 링크를 아는 사람이 가짜 신호를 보낼 수 있다. 신호에 내용이 없어 최악의 경우가 불필요한 새로고침이다.
- 낙관적 값은 만들 때의 서버 값을 함께 기억하므로, 갱신이 도착하면 자동으로 서버 값에 자리를 내준다.
