# Plypick 백로그 (2026-09-20 검토 기준)

실제 화면(plypick.kr)과 코드, 프로덕션 데이터, 경쟁 서비스(bluepick.app)를 보고 정리했다.
각 항목에 **왜**와 **근거**를 붙였다. 근거가 "가설"인 항목은 먼저 검증한다.

## P0 — 지금 사용자가 겪고 있는 문제

### 1. 모바일 투표 카드에서 곡 제목이 잘린다

- **근거(관찰)**: `Z48RihwS` 방 34곡 중 대부분이 8자 근처에서 끊김.
  `Bill Wit...` `Event H...` `백예린 (...` `[11회 풀...` `왜 그래 (...`
- **원인**: `src/components/SongCard.tsx:171` 이 `truncate`(1줄). 375px 에서
  재생버튼(44) + 투표 묶음(약 120) + 더보기(44) 를 빼면 제목에 약 135px 만 남는다.
  데스크톱에서는 멀쩡해서 개발 중에 안 보인다.
- **해법**: 셋리스트 화면이 이미 잘 하고 있다(썸네일 + 2줄 제목). 같은 패턴으로 맞춘다.
  `truncate` → `line-clamp-2`, compact 뷰에도 썸네일 노출.
- **규모**: 반나절

### 2. 모바일에서 다음 곡 자동 진행이 안 된다

- **원인(코드)**: `src/components/YouTubePlayer.tsx:90` 의 `key={videoId}` 가
  곡이 바뀔 때마다 iframe 을 파괴하고 새로 만든다. 새 iframe 은 사용자 제스처와
  연결이 끊겨 `autoplay=1` 이 차단된다. 브라우저 정책 자체보다 구조 문제다.
- **확인 방법**: 실제 폰에서 "한 곡 반복"과 "다음 곡 넘김"을 비교한다.
  반복만 되면 진단이 맞다(반복은 같은 iframe 을 유지한다).
- **해법**: 플레이어 인스턴스를 `PlaylistClient` 레벨로 올려 하나만 유지하고,
  곡 전환을 이미 있는 `loadVideoById()` 로 처리한다. 카드에는 자리만 둔다.
- **참고**: `playsinline=1`, `allow="autoplay"` 는 이미 올바르다. 건드리지 않는다.
- **규모**: 1일 (구조 변경)

## P1 — 핵심 마찰 제거

### 3. YouTube Data API: 재생시간 자동 + 임베드 가능 검사

- **근거(관찰)**: 합주 모드에서 셋리스트 12곡 **전부** `+ 메타 추가 (키·BPM·난이도...)`
  상태다. 키·BPM 이 한 곡도 안 채워져 있다. 재생시간만 채워져 있는데, 이건 셋리스트
  토탈 시간을 보려고 분·초를 손으로 입력한 것이다.
- **왜**: 수동 입력은 실제로 안 쓰인다. 자동으로 채워지는 것부터 채운다.
- **방법**: `videos.list?part=contentDetails,status` — ISO 8601 duration 을 초로,
  `status.embeddable` 로 합주 중 재생 불가 곡을 미리 거른다.
- **비용**: 1 유닛 / 호출, 50개 묶음 가능. 사실상 부담 없음.
- **규모**: 반나절 (+ API 키 발급)

### 4. YouTube 검색으로 곡 추가

- **근거**: 현재 곡 추가 경로가 URL 붙여넣기 하나뿐.
- **쿼터 제약(확인됨)**: `search.list` 는 **하루 100회 전용 쿼터**. 나머지 엔드포인트가
  1만 유닛을 공유. 전체 사용자 합산 100회라 설계로 막아야 한다.
  - 키 입력마다 호출 금지. 엔터/돋보기 버튼으로 명시적 검색
  - 같은 검색어 캐싱(쿼리 → 결과, 24시간). 밴드들은 비슷한 곡을 찾는다
  - URL 붙여넣기를 계속 메인 경로로 유지(`videos.list` 1유닛)
- **플로우**: 검색 → 결과 카드(썸네일·제목·채널·길이) → 인라인 미리듣기 → 후보곡 추가
- **결과에 길이를 함께 표시**: `search.list` 는 길이를 안 주므로 결과 videoId 를
  `videos.list` 에 한 번 묶어 보낸다(3번과 같은 호출).
- **규모**: 1일

### 5. invidious 죽은 코드 제거

- **근거**: `src/lib/invidious.ts` 의 `searchVideos` 와 `src/components/SearchResults.tsx`
  를 **어디서도 호출하지 않는다**. 공개 인스턴스 3개 중 `vid.puffyan.us` 는 오래전부터 불안정.
- **추가 이유**: 비공식 YouTube 프론트엔드라 쿼터 증설 심사(아래 참고) 때
  불필요한 위험이 된다.
- **규모**: 30분. 4번과 함께 처리.

### 6. 기명 모드 투표자 표시 압축

- **근거(관찰)**: 34곡 리스트에서 모든 행에 `김주하 · 김윤지 · 나윤 · 이도겸 · 김예지`
  가 깔려 시각적 소음이 크고 행 높이가 두 배가 된다.
- **해법**: 접어두고 탭하면 펼치기, 또는 아바타/개수 요약.
- **규모**: 2시간

### 7. 비로그인 상태 시각 처리

- **근거(관찰)**: 로그인 안 한 방문자에게 투표 버튼이 **활성처럼** 보인다.
  누르면 카카오 로그인으로 가는데 예고가 없다. 초대받은 멤버의 첫 화면이다.
- **규모**: 2시간

### 8. 후보곡 정리 수단

- **근거(관찰)**: 한 방에 34곡이 정리 없이 쌓여 있다. 지우는 것 말고는 방법이 없다.
- **해법 후보**: 탈락곡 접기, "이번 라운드" 개념, 보관 처리.
- **규모**: 1일 (설계 필요)

## P2 — 인프라 · 운영

### 9. Supabase 서울 리전 이전

- **상태**: 런북과 스크립트 준비 완료. 날짜만 잡으면 된다.
- **문서**: `docs/plans/2026-09-20-supabase-region-migration.md`
- **근거(실측)**: 현재 `ap-southeast-1`. Vercel 함수(icn1) → DB 왕복 약 130ms.
  합주방 TTFB 0.65초 중 약 0.36초가 DB 대기.
- **기대**: 왕복 5~15ms, TTFB 0.4초 안팎
- **주의**: `auth.users` 이전 실패 시 방장 권한·투표 기록이 끊어진다. 대조 필수.

### 10. cron 자동 확정의 실시간 알림 누락

- **내용**: Vercel Cron 이 서버에서 단독으로 만드는 변경이라 열려 있는 화면에
  broadcast 알림이 가지 않는다.
- **가치**: 낮음. KST 자정에 실행되고 그 시각에 화면 열어둔 사람이 거의 없다.
- **규모**: 30분. **당분간 보류 권장.**

### 11. 레이트리밋이 람다 인메모리

- **내용**: `src/proxy.ts` 의 Map 기반. 람다마다 따로 센다.
- **가치**: 중간-낮음. v15 로 쓰기 경로가 이미 계정 소유 검사를 통과해야 한다.
- **비용**: Upstash/Vercel KV 등 외부 서비스 추가.
- **규모**: 2~3시간. **보류.**

### 12. 카카오 JavaScript 키 인라인

- **내용**: `src/app/layout.tsx` 에 인라인. 원래 브라우저에 노출되는 공개 키다.
- **가치**: 거의 없음. 배포 없이 키 교체하는 정도.
- **규모**: 15분. **보류.**

### 13. 빈 테스트방 14개 삭제 여부

- **근거(실측)**: 보관 합주방 24개 중 14개가 곡 0개 테스트방
  (`Testsetset`, `ㅇㅇㅇ`, `teststst`, `ㅋㅋㅋ` 등).
- **판단 필요**: 홈 통계 `합주 37` 에 포함돼 있다. 지우면 23으로 **정직해지지만
  숫자는 작아진다.** 되돌릴 수 없다.
- **규모**: 20분 + 결정

## P3 — 제품 확장 (가설. 검증 후 착수)

BluePick 과의 관계: 겹치는 건 **타겟이지 하는 일이 아니다.** BluePick 은 혼자 연습 +
지역 탐색 + 구인 커뮤니티 + AI 코칭(구독 ₩7,900/월, 네이티브 앱, 2,882명).
**투표도 셋리스트도 없다.** Plypick 은 "팀 의사결정"을 비어 있는 자리로 갖고 있다.

### 14. 합주 일정 잡기
날짜가 투표 마감 하나뿐이다. "다음 합주 언제?"도 단톡방에서 똑같이 미뤄지는 일이고,
곡 결정과 한 화면에 있는 게 자연스럽다. 참석/불참 표시까지.

### 15. 곡별 파트 분담
기타1/기타2/베이스/드럼/보컬 누가 맡을지. 합주 준비의 실제 마찰이고 BluePick 에 없다.

### 16. 곡별 연습 상태
"연습함 / 미흡" 표시로 합주 전에 어디가 약한지 팀이 공유.

### 17. 셋리스트 히스토리
지난 공연 셋리스트 보관·재사용. 밴드는 레퍼토리가 누적된다.

### 18. 우리 키 기록
페르소나 용어에 "키 변경"이 있다. 원곡 키와 실제 연주 키를 따로.

### 하지 말 것
개인용 연습 도구(연습 기록, AI 코칭, 지역 탐색)로 넓히는 것.
BluePick 이 이미 규모와 네이티브 앱을 갖고 하고 있다. 정면 충돌에서 이길 이유가 없다.
**Plypick 의 자산은 "팀"이다.**

## 참고: YouTube Data API 쿼터 증설 (확인됨)

**GCP 콘솔에서는 증설할 수 없다.** 다른 Google API 처럼 슬라이더로 올리는 방식이 아니다.

1. **YouTube API Services - Audit and Quota Extension Form** 을 제출한다
2. YouTube API Services 약관과 Developer Policies 준수 여부를 **심사**받는다
3. YouTube API Services 팀이 연락한다. **소요 기간은 명시돼 있지 않다**
4. 12개월 내 심사를 통과했다면 같은 폼으로 추가 증설을 요청한다
5. 반려 시 Appeals Form

기본 할당: `search.list` 100회/일, `videos.insert` 100회/일,
그 외 전체 합산 10,000 유닛/일. 태평양 시간 자정에 초기화.

**심사 전에 정리해둘 것**
- invidious(비공식 YouTube 프론트엔드) 코드 제거 — 5번
- 공식 IFrame 플레이어로만 재생 (이미 그렇다)
- **저장한 API 데이터의 보관 정책 확인 필요.** Developer Policies 는 API 로 받아온
  데이터의 갱신·삭제 주기를 정하고 있다. 현재 제목·썸네일 URL 을 DB 에 무기한
  저장하는데, oEmbed 기반이라 지금은 범위 밖일 수 있으나 Data API 로 바꾸면
  이 규정이 적용된다. **착수 전에 원문을 확인할 것.**

결론: 증설은 가능하지만 **시간이 걸리고 보장되지 않는다.**
4번의 캐싱 설계를 "증설되면 풀 임시방편"이 아니라 **기본 설계**로 가져간다.
